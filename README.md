# マニアスタジアム（Phase 1: MVP）

サッカー(欧州リーグ)・NBA・MLB・ボクシングを、順位表・試合結果/日程・
「読み物」(歴史や文化のマニアックな解説記事)で追いかける観戦アプリ（PWA）です。

## Phase 1でできること

- 🏠 **ホーム**：アプリを開いて最初に見える画面。「結果の一覧」ではなく「今スポーツ界で起きていること」を伝える
  - ⭐ 推し：登録したチーム・選手の成績/次の試合/関連ニュースを一番上に表示。チーム詳細
    ページ・選手カードの☆をタップして登録する(この端末のブラウザに保存、他端末とは同期されない)
  - 📰 注目ニュース（ESPNの編集記事。見出し・写真・要約。Gemini APIキーがあれば日本語に自動翻訳）
  - 📅「今週の注目カード」・🏆「チャンピオンへの道」はタイトルだけ横並びで表示し、
    タップしたものだけその場で詳細が展開する(無駄な余白を作らないため)
    - 注目カード: エル・クラシコ等のダービー、無ければ首位対決を自動検出。ダービーには歴史的背景の解説つき
    - チャンピオンへの道: MLB/NBAのプレーオフ開幕までの正確なカウントダウン(ESPNの公式
      シーズン日程から計算)とフォーマット解説、サッカー各リーグの優勝争い・残留争いの勝点差、
      ボクシングの王座統一戦の仕組み
  - 🥊 ボクシング速報（直近の注目カード）
- ⚽ サッカー：プレミアリーグ / ラ・リーガ / セリエA / ブンデスリーガ / リーグ・アン / チャンピオンズリーグ の順位表・試合結果
- 🏀 NBA・⚾ MLB：順位表・試合結果/日程
- 🥊 ボクシング：主要カードの試合予定（手動更新）
- 📖 各スポーツに「読み物」タブ：歴史的背景・魅力・現地の空気感を解説する記事
- 🔥 各スポーツの「順位表」タブ上部に「好調なチーム」の帯を表示（連勝中: NBA/MLBは3連勝以上・
  サッカーは今季無敗で全勝／直近試合の勝率: 直近最大10試合を集計し勝率7割以上のチームを自動検出、
  Gemini APIキーがあれば一言解説つき）。タップでチーム詳細ページへ(以前はホーム画面にあったが、
  各スポーツのページで見る方が分かりやすいとのことで移動した)
- 👤 順位表のチーム名をタップするとチーム詳細ページ（今シーズンの成績・直近/予定の試合・
  選手ロスター）を表示。選手の顔写真はESPNのデータにあるものだけ表示され、無い選手は
  チームロゴで代用される（特にサッカーの控え選手・若手は写真が無いことが多い）

データはESPNの公開API(非公式・キー不要)を利用しています。将来的にAPI仕様が変わる可能性はありますが、
広く使われている安定した情報源です。

まだ入っていない機能（次のフェーズで追加予定）:
NFL・F1・ゴルフの追加、移籍・トレード情報、過去の試合ハイライト動画、現地観戦ガイド

## データの取得方式について（重要）

ESPNの公開APIはブラウザからの直接呼び出しをCORSでブロックするため、アプリ(ブラウザ)から直接
`fetch` することはできません。そのため以下の方式にしています。

1. GitHub Actions (`.github/workflows/update-data.yml`) が15分おきに
   `scripts/fetch-espn-data.mjs` をサーバー上で実行し、ESPN APIから順位表・試合データを取得
2. 取得結果を `public/data/*.json` として自動コミット
3. その push をきっかけに `deploy.yml` が走り、最新データを含んだサイトが再ビルド・再公開される

つまりアプリが表示するのは「最大15分前時点」のデータです。速報性は多少落ちますが、
ブラウザでのCORSエラーを避けて安定して表示できます。手元で試すときは、事前に一度
`node scripts/fetch-espn-data.mjs` を実行して `public/data/` を作ってから `npm run dev` してください
(このJSONが無いと順位表・試合は「データを取得できませんでした」と表示されます)。

**重要**: `public/data/` 配下のJSONはPWAのService Workerのプリキャッシュ対象から
明示的に除外しています(`vite.config.js` の `workbox.globIgnores`)。ここを外すと、
アプリがビルド時点のデータをずっとキャッシュし続けてしまい、サーバー側が更新されても
「アプリだけ表示が古いまま」になるバグが起きます(2026-09-10に実際に発生し原因判明)。
新しく `public/data/` 配下にファイルを追加するときも、この除外設定はそのままにしてください。

**アプリ本体(JS/CSS)の更新について**: `public/data/`の対策とは別に、コード自体を更新した
ときにホーム画面/Dockに追加した(=開きっぱなしになりがちな)アプリが古いままになる問題も
あった。ページ遷移が起きないスタンドアロン表示では、ブラウザが自発的に新しいService Worker
を探しに行く機会がほとんど無いため。`src/main.jsx`で`virtual:pwa-register`を自前で呼び、
1分おきに`registration.update()`で能動的に更新確認し、見つかり次第自動でリロードするように
した(`vite.config.js`は`injectRegister: false`にして、素の`registerSW.js`は使っていない)。

## ホーム画面の「注目カード」判定ロジックについて

`src/data/rivalries.js` に手動で登録した伝統の一戦・人気カード(エル・クラシコ、マンチェスター・
ダービーなど)を優先的に表示し、該当する試合が無いリーグでは順位表の首位同士の対戦を自動的に
拾います。新しいライバル関係を追加したいときはこのファイルにteam idのペアを追記してください
(team idは `public/data/team/<sportPath>-<teamId>.json` のファイル名と対応します)。

各ダービーには `background` として歴史的・文化的な背景の解説文を手動で書いています。
AIにその場で生成させると年代や記録を間違えるリスクがあるため、ここは事実確認した文章を
直接書く方針にしています(自動検出される「首位対決」のような一時的なカードには付きません)。

「直近試合の勝率が高いチーム」は、現在の連勝数だけだと連勝が直近で途切れた好調なチームを
見逃してしまうため、`scripts/fetch-team-details.mjs` が各チームの直近最大10試合の結果を
別途取得して勝率を計算し、7割以上のチームを `public/data/hot-teams.json` にまとめています。
これも1日1回、ロスターと同じタイミングで更新されます。

## チームロスター(選手一覧)の更新について

チーム詳細ページのロスターは `.github/workflows/update-team-data.yml` が1日1回
(`scripts/fetch-team-details.mjs`)自動更新します。試合速報ほど頻繁に変わらないため、
順位表・試合速報(15分おき)とは別のスケジュールにしています。

## 推し(お気に入り)チーム・選手について

このアプリにはログイン機能が無いため、推しの登録は`localStorage`でこの端末(ブラウザ)にだけ
保存しています(`src/utils/favorites.js`)。他の端末やブラウザとは同期されません。
チーム詳細ページのチーム名の横、および選手カードの☆をタップして登録/解除します。
ホーム画面の「⭐ 推し」セクションに、登録したチームの成績・次の試合、選手の所属チーム・
背番号・関連ニュース(見出し・要約に名前が含まれる注目ニュースを検索)が表示されます。
チーム詳細ページ自体にも「📰 チーム関連ニュース」(チーム名の愛称部分で検索)と
「⭐ 推し選手の関連ニュース」を表示し、推しの情報をそのページでまとめて確認できます。

ボクシングにはチーム/ロスターの概念が無いため、選手(ボクサー)単体の推し登録に対応しています。
「ボクシング」タブの各試合カードで、選手名の☆をタップして登録します(`playerId`はESPNの
選手IDが無いため名前そのものをキーに使用)。ホームの推しカードでは、`src/data/boxingSchedule.json`
の`fighters`配列と名前が一致する次の試合を表示します(チームが無いためタップしても遷移しません)。

次戦がまだ発表されていない選手(例: 井上尚弥)も、「ボクシング」タブ上部の入力欄に名前を
直接入力して推し登録できます。ESPNにはボクシングのニュース・個人成績データがそもそも
存在しないため、代わりに `src/data/boxerProfiles.json` に主要選手のプロフィール
(階級・王座・戦績)を手動で用意しています。「◯◯選手のプロフィールを追加/更新して」「◯◯選手の
最近のニュースを調べて」と頼んでもらえれば、Web検索で確認してから`recentUpdate`フィールドに
追記します(適当な数字・情報を書かない方針)。

**アプリ自体に「更新ボタンを押すとその場でニュースを検索する」機能は付けていません**。
このアプリは(サーバーを持たない)静的サイトなので、実行時にAIで検索する仕組みを組み込めない
ため。代わりに推しボクサーのカードに **𝕏で検索 / 🔍ニュース検索** の外部リンクボタンを
用意し、ワンタップで検索結果に飛べるようにしています。

## 選手個人の成績について

NBA・MLBはESPNの個人成績API(`common/v3/sports/{sport}/{league}/athletes/{id}/stats`)から
最新シーズンの主要な数字(NBA: 得点/リバウンド/アシスト、MLB: 打率/本塁打/打点、または
防御率/勝敗)を取得し、ロスターの選手カード・推し選手カードに表示しています
(`scripts/fetch-team-details.mjs`が1日1回、ロスターと同時に取得)。
**サッカーはこのAPIが「Statistics not found」を返し、個人成績データがそもそも存在しません**
(選手の顔写真が少ないのと同じ制約)。ボクシングも同様に個人成績データはありません。

## プレーオフまでの日数について

`scripts/fetch-season-milestones.mjs`(update-team-data.ymlで1日1回実行)が、ESPNの
公式シーズン日程API(`sports.core.api.espn.com`の`seasons/{year}/types/{1,2,3}`)から
プレシーズン・レギュラーシーズン・ポストシーズンそれぞれの開始日/終了日を取得し、
「今日から何日か」を計算しています。適当な日付を決め打ちすると信頼を損ねるため、
必ず実データから計算する方針です。ESPNのシーズン年ラベルの付け方が競技によって
違う(MLBはカレンダー年、NBAはシーズン終了年)ため、今年と来年の両方を取得して
実際に「今」を含む/次に来る区間を判定しています。

## AI機能(ニュース翻訳・好調チーム解説)について

`GEMINI_API_KEY` を GitHubリポジトリの Secret(Settings > Secrets and variables > Actions)に
登録すると、以下の機能が有効になります(未設定でも他の機能は今まで通り動きます)。

- 📰 注目ニュースの見出し・要約を日本語に自動翻訳(`scripts/fetch-news.mjs`)
  - 同じ記事を15分おきに毎回翻訳し直すと無駄なので、前回の翻訳結果を使い回すキャッシュが入っています
- 🔥 好調なチームの一言キャッチコピー(`scripts/fetch-team-details.mjs`)
  - 「◯勝◯敗」という実際の記録だけを根拠にするようプロンプトで縛っており、
    選手名など持っていない情報をAIが作文しないようにしています

Gemini APIキーの取得は[Google AI Studio](https://aistudio.google.com/apikey)から無料で可能です。
共有のロジックは `scripts/gemini.mjs` にまとまっています。

## ボクシング日程の更新について

ボクシングには安定した無料APIが無いため、`src/data/boxingSchedule.json` を手動で更新しています。
最新の日程に更新したいときは「ボクシングの日程を更新して」とMulmoClaudeに頼んでください。

**重要**: 過去に手作業で更新した際、実在しない/日付が誤った試合情報(例: とっくに終わっている
はずの試合を「これからの試合」として記載)が混入していたことがある(2026-09-11発覚)。
更新するときは記憶や推測で書かず、必ずWeb検索で1件ずつ実在・日時・会場を確認してから記載すること。

## GitHub Pagesへの公開手順

御蔵島図鑑アプリと同じ手順です。

1. このフォルダをGitHub上のリポジトリ（例: `sports-mania`）にpush する
2. `Settings > Pages` で Source を **GitHub Actions** にする
3. `main` にpushすると自動でビルド＆公開される
4. `https://<ユーザー名>.github.io/sports-mania/` で公開される

APIキーの設定は不要です（ESPNの公開APIはキー不要のため）。
